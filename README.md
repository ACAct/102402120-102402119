# 校园失物招领（Campus Lost & Found）

> FZU 软件工程结对作业 2 —— 基于第一次结对作业原型设计完成的 WEB 端核心功能实现。

一个面向校园的失物招领平台，覆盖 **发布信息 → 浏览/搜索 → 查看详情 → 联系发布者 → 更新状态** 的完整流程。

---

## 一、快速开始

**零依赖、零构建、零安装**：下载本项目全部文件后，用 **谷歌浏览器（Chrome）** 直接打开根目录下的 `index.html` 即可。

```
双击 index.html          # 或在 Chrome 中「文件 → 打开」选择 index.html
```

> 项目使用原生 HTML + CSS + JavaScript，不需要 Node.js、不需要 `npm install`、不需要启动服务器。
> 所有跳转都使用真实 `<a href>` 页面跳转，因此在 `file://` 协议下也能正常工作。

### 页面导航

| 页面 | 文件 | 说明 |
| --- | --- | --- |
| 首页 | `index.html` | 信息流浏览、类型筛选、排序、热门搜索入口 |
| 搜索页 | `search.html` | 关键词检索、类型筛选、搜索历史与无结果引导 |
| 详情页 | `detail.html?id=xxx` | 完整信息 + 联系方式 + 一键复制 |
| 发布页 | `publish.html` | 发布寻物启事 / 失物招领（含必填校验） |
| 我的发布 | `myposts.html` | 管理自己发布的信息、修改状态 |
| 发布成功 | `success.html` | 发布结果与后续引导 |

### 建议体验路径

1. 打开 `index.html`，点击「我要寻物」或底部「发布」，填写并发布一条信息；
2. 关注发布页的**必填校验**：留空直接提交会逐项报错；
3. 回到首页，用搜索框或热门关键词搜索刚发布的内容；
4. 点击卡片进入详情页，点击「联系发布者」并试用**一键复制**；
5. 进入「我的发布」，把某条信息标记为「已找到 / 已归还」，再回首页观察状态变化。

### 为什么这样组织

- **`core` / `data` / `components` / `pages` 四层分离**：搜索、校验这些「最需要被测试」的逻辑全部放在 `core` 与 `data` 中，不依赖 DOM，可以直接用 Node 断言；`pages` 只负责渲染与事件绑定。
- **每个 JS 文件都是 UMD 包装**：同一份源码既能用 `<script>` 在浏览器加载（挂到 `window.LF.*`），也能被 Node `require()` 用于单元测试，不需要复制代码或引入打包工具。
- **页面通过统一的 `data-*` 属性与事件委托交互**：`layout.js` 中的路由表是唯一的路径来源，避免各页面散落硬编码文件名。
- **设计令牌单一来源**：原型的 6 个页面各自内联了同一套 CSS 变量，这里抽取为 `tokens.css`，杜绝多处定义漂移。

## 三、功能说明

### 首页（`index.html`）
- 信息流卡片展示类型徽章、状态、名称、描述摘要、地点与发布者；
- **进行中优先**排序：已解决的信息整体降饱和并排在列表末尾；可切换为「最新发布」；
- 分段筛选：全部 / 寻物 / 招领；
- 数据概览：进行中、寻物启事、失物招领、已解决的数量；
- 热门关键词快捷入口，一键带参跳转搜索页；
- 空状态按筛选类型给出不同文案与对应的发布引导。

### 搜索页（`search.html`）
- **实时搜索**：输入即筛选，无需点击按钮（也支持回车与搜索按钮）；
- 关键词归一化：全角自动转半角、大小写不敏感、忽略首尾与多余空白；
- 中文按**子串匹配**（「校园卡」可命中「黑色校园卡」），多关键词之间是「与」关系；
- **相关性排序**：标题 > 分类 > 地点 > 类型 > 发布者 > 描述；标题完全匹配额外加成；同分时进行中优先；
- 命中关键词高亮，并标注命中字段（如「命中地点」）；
- **无结果时给出替代关键词**，而不是只留一句「没有找到」；
- 搜索历史（去重、置顶、上限 8 条、单字不记录）。

### 详情页（`detail.html?id=xxx`）
- 完整展示名称、类型、状态、分类、时间、地点、描述、发布者与发布时间；
- 时间/地点标签随类型切换：寻物为「丢失时间/地点」，招领为「拾取时间/地点」；
- 联系方式卡片支持**一键复制**（优先使用异步剪贴板 API，失败自动回退）；
- 已解决的信息保留全部内容便于核对，但联系方式降权并注明无需再联系，底部操作区改为「已完成，无需联系」；
- `id` 缺失或不存在时给出明确提示与返回入口，不会白屏。

### 状态维护（`myposts.html`）
- 由发布者把自己发布的信息标记为「已找到」（寻物）或「已归还」（招领），也可撤销该标记；
- 状态一旦更新，首页、搜索页、详情页会同步呈现（列表降权、徽章变更、联系入口收敛）；
- 统计概览展示「共发布 / 进行中 / 已解决」的数量变化。

> 状态由「信息类型 + 是否已解决」派生，因此不会出现「寻物 + 已归还」这类自相矛盾的组合。
>
> 「我的发布」如何识别本人：本项目不引入登录与实名体系，改用**浏览器本地记录发布时填写的称呼**来筛选。首次打开该页面（本地还没有发布记录）时会展示全部信息作为演示，并在页面上明确说明这一点。

### 发布页（`publish.html`）
- 寻物/招领类型卡片切换，标签与提示文案随类型联动，切换时**保留已填内容**；
- 逐字段即时校验（必填、长度、时间不得晚于当前），提交失败时滚动并聚焦到首个出错字段；
- 开始修正某一项时立即清除该项错误提示；名称与描述实时字数统计；
- 丢失/拾取时间默认预填当前时间，减少一次必填操作；
- 提交成功后跳转发布成功页，展示刚发布信息的摘要与后续入口。

## 四、数据结构设计

单条信息（`Item`）的字段规范定义在 `js/data/item.js` 的 `defineSchema()` 中，是数据结构的自描述来源：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 信息编号，形如 `LFL20261001A3F9K`，同一仓库内唯一 |
| `type` | enum | 是 | `lost` 寻物启事 / `found` 失物招领 |
| `title` | string | 是 | 物品名称，≤ 30 字 |
| `description` | string | 否 | 物品描述，≤ 200 字 |
| `category` | enum | 否 | 物品分类：证件卡类 / 数码电子 / 雨伞雨具 / 钥匙挂件 / 书籍资料 / 衣物配饰 / 水杯餐具 / 其他 |
| `location` | string | 是 | 丢失或拾取地点，≤ 40 字 |
| `locationDetail` | string | 否 | 地点补充说明 |
| `lostAt` | datetime | 是 | 丢失或拾取时间，不得晚于当前时间 |
| `publishedAt` | datetime | 否 | 发布时间，由系统写入 |
| `contactType` | enum | 是 | `wechat` / `qq` / `phone` / `other` |
| `contactValue` | string | 是 | 联系方式内容，≤ 60 字 |
| `publisher.name` | string | 是 | 发布者称呼，≤ 20 字 |
| `publisher.dept` | string | 否 | 发布者院系 |
| `resolved` | boolean | 否 | 是否已找到 / 已归还，默认 `false` |
| `resolvedAt` | datetime | 否 | 标记解决的时间 |
| `status` | derived | — | 由 `type + resolved` 派生，**不接受外部赋值** |

状态派生规则：

| 类型 | `resolved` | 状态 | 文案 |
| --- | --- | --- | --- |
| `lost` | `false` | `ongoing` | 寻找中 |
| `lost` | `true` | `found` | 已找到 |
| `found` | `false` | `waiting` | 待认领 |
| `found` | `true` | `returned` | 已归还 |

数据流：`seed.js`（种子）或表单 → `item.normalize()` 收敛 → `repository`（内存 + 可选 localStorage）→ 页面读取渲染。

**健壮性约定**：非法枚举与非法时间会被降级为默认值而不是抛异常；未知字段一律丢弃。这样单条脏数据不会让整页白屏。

### 关于数据持久化

数据访问层会尝试使用 `localStorage` 保存新发布的信息；**当浏览器限制本地存储时（部分浏览器在 `file://` 协议下会拒绝），应用会自动退化为内存态**，所有功能仍然可用，只是刷新后回到初始演示数据。这是为了让「双击 html 即可运行」这一要求在任何环境下都成立。

## 五、单元测试

测试使用 Node.js 内置测试框架（`node:test` + `node:assert`），**不需要安装任何第三方依赖**。

```bash
# 方式一：测试总入口（推荐，任何环境都能跑）
#   先跑逻辑单元测试，再跑 5 组页面冒烟检查
node tests/run-all.js

# 方式二：Node 官方测试运行器（仅逻辑单元测试，会为每个测试文件启动子进程）
node --test tests/

# 方式三：通过 npm 脚本
npm test
```

当前测试规模：**56 个逻辑单元测试用例 + 5 组页面冒烟检查（共 40 个断言场景）**。

| 测试文件 | 覆盖内容 |
| --- | --- |
| `tests/item.test.js` | 字段规范化、非法枚举/时间降级、XSS 字符保留、必填校验、长度边界（30/31 字）、未来时间拒绝、时钟误差容忍、纯空白视为未填、状态流转、种子数据、仓储增删改查与排序 |
| `tests/search.test.js` | 子串与多字段命中、大小写不敏感、全角转半角、多关键词「与」关系、空查询、无结果、正则元字符安全、相关性排序、类型过滤、高亮转义 |
| `tests/smoke-home.js` | 首页渲染条数、排序顺序、筛选结果、导航外框注入 |
| `tests/smoke-search.js` | 带参进入、关键词高亮、类型叠加筛选、无结果引导、搜索历史去重与上限 |
| `tests/smoke-detail.js` | 字段完整性、措辞随类型切换、已解决降权、无效 id 提示、XSS 注入防护、路由编码往返 |
| `tests/smoke-publish.js` | 表单渲染、必填校验不入库、长度边界、未来时间拒绝、类型切换保留输入、提交跳转参数 |
| `tests/smoke-myposts.js` | 成功页摘要与降级、我的发布身份筛选、状态维护闭环（标记/撤销 + 同步）、空状态 |

`tests/dom-harness.js` 是一个极简 DOM 桩，用 `vm` 模块加载浏览器脚本，从而在没有浏览器的环境下验证「页面初始化 → 渲染出内容」这条链路。

## 六、已知边界

- 本项目为**纯前端演示实现**，不包含后端服务、实名认证、即时聊天与地图定位（与作业要求一致）；
- 联系方式为发布者自行填写，平台不参与交易，详情页已给出防诈骗提示；
- 数据保存在浏览器本地，清除浏览器数据后会恢复为初始演示数据。
